# 20261022-10 选股池页面功能实测与缺陷分级

## 背景 / 目标

承接 2026-10-22 全库优化审计（已建 #8–#21），本轮聚焦用户指定的范围：**选股池相关页面（三池选股）是否存在 bug，逐页验证功能是否完整**。

目标：
1. 8 个页面逐张实测渲染与交互，确认前端模块化拆分（#12 已合并）后没有断链。
2. 对四个「三池」页面（策略选股 / 公告选股 / 预测选股 / 热门智能）验证候选 → 重点 → 买入的实际可用性。
3. 发现的缺陷回原文核实行号与运行时证据后，按 P0/P1/P2/P3 分级建单。

本轮为**只读实测 + 缺陷建单**，未修改任何业务代码。

## 实测方法

- 本地服务：`PYTHON_BIN=/opt/homebrew/bin/python3 ./start.sh` → `http://127.0.0.1:18890`（仅开发调试，非交付）。
- 接口层：对 27 个页面依赖接口逐一 `curl`，全部 200，无 4xx/5xx。
- 页面层：Playwright（headless chromium）逐 tab 切换，采集 console 错误、`requestfailed`、HTTP≥400、三池 DOM 计数与卡片内容。
- 交互层：实测「立即扫描 / 公告筛选 / 立即分析 / 立即预测 / 概念筛选 / 关键词筛选 / 池迁移 / 策略新建-保存-删除 / 费用设置 / 实时推送」。
- 一致性检查：脚本比对 `js/*.js` 中全部 `getElementById` 目标与 `index.html` 的 id 集合。

## 关键决策记录

1. **在本地实例而非线上做破坏性交互测试**。线上 `alpha.notenap.com` 是共享实例，扫描/筛选/买卖会污染其状态；本地已有 960MB K 线缓存，足够复现。修复交付仍需按 AGENTS.md 走 main + CI。
2. **撤回两条初判 bug**。「数据中心整页不渲染」与「前端 DOM 断链」在复测中不成立：前者是接口偶发慢响应叠加无超时（改立 #55），后者 `btnDcReportSort` 是 `dcReportSort` 内动态生成的子元素，属误报。
3. **`扫描完成：命中 0 只` 未建单**。实测 `total_hits` 字段存在且提示正确（命中 2 只），说明此前对该字段的担心不成立。
4. **#50 定为 P1 而非 P2**。它不是显示问题：`funnel_service.move_pool` 明确拒绝策略命中股，意味着「选股 → 模拟盘」这条产品主链路整体不可用。
5. **#51 与 #52 分开建单**。前者是数据正确性（算错），后者是分层可用性（阈值失配），修复责任与验证方式不同，合并会掩盖各自的验收标准。
