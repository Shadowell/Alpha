# 全库 Bug 审查修复方案

> 来源：2026-08-24 全库代码审查（3 个并行子代理 + 人工验证关键项）。本文件只增不删，后续修订另起新文件。

## 背景 / 目标

对 Alpha 全库（约 1.7 万行 Python + 前端 JS）做了系统性 Bug 审查，确认 5 个严重问题、12+ 个中等问题。核心目标：

1. 恢复两个实际失效的核心功能（盘中 Kronos 监控、公告 LLM 打分）。
2. 消除安全裸奔面（0.0.0.0 + 零鉴权 + CORS 全开 + XSS）。
3. 修复数据正确性漏洞（盘中脏 bar 固化、复权混源、部分成功封账）。
4. 消除事件循环阻塞点（Torch 训练、同步 requests、大 SQL）。

## 任务分解（checklist）

### 第一批：功能失效级（立即修）

- [ ] **F1. `hermes_runtime.py:758` KronosPredictService 缺参**
  - 现状：`KronosPredictService()` 无参构造，构造函数要求 `(kline_store, provider)`，buy/focus 池非空时监控 tick 必抛 TypeError。
  - 方案：main.py 启动时已构建共享 `kronos_predict_service`；通过 `HermesRuntime.__init__` 注入该实例（新增可选参数），758 行改为复用注入实例，不再临时 new。保持向后兼容默认 None，None 时跳过 Kronos 段并记日志。

- [ ] **F2. `notice_llm.py` 同步 requests + 静默失败 + 硬编码端点**
  - `score_with_llm` 改为 async：用共享 `httpx.AsyncClient`（或最小改动 `asyncio.to_thread(requests.post, ...)`）。
  - 尊重 `OPENAI_BASE_URL` / `HERMES_MODEL` 环境变量，去掉硬编码 `https://api.openai.com/v1/responses`；未配置 key 时直接返回 `( {}, False)` 跳过打分。
  - `except Exception` 分支改为返回 `( {}, False)` 并 `log.exception(...)`。

### 第二批：安全加固

- [ ] **S1. 监听地址**：`start.sh:18` 默认 HOST 从 `0.0.0.0` 改为 `127.0.0.1`（保留环境变量覆盖能力，README 注明远程部署方法）。
- [ ] **S2. 写操作鉴权**：新增 FastAPI dependency `verify_write_key`——若 `.env` 配置了 `ALPHA_WRITE_TOKEN`，则所有 POST/DELETE/PUT 路由校验 `X-Alpha-Token` 头；未配置 token 时仅允许来源 IP 为回环地址的请求（LAN 请求返回 403）。
- [ ] **S3. CORS 收敛**：`allow_origins=["*"]` 与 `allow_credentials=True` 二选一——改为 origins 白名单（`http://127.0.0.1:18888` 等，可由 env 扩展），去掉 credentials 或去掉通配符。
- [ ] **S4. XSS**：`static/notice.js` 所有插值过已有 `esc()`；外链 href 校验仅允许 `http(s):`。`static/app.js` 中 `stock.name/tag.name/item.name/data-name` 等插值统一过 esc。
- [ ] **S5. MCP symbol 校验**：`mcp_server.py` 入口统一 `re.fullmatch(r"\d{6}", symbol)`，不合法直接报错。

### 第三批：数据正确性

- [ ] **D1. 禁止盘中/盘前 spot 落正式 bar**：`kline_cache_service.py` spot 补缺路径仅在本地时间 ≥15:10（Asia/Shanghai，用 `now_cn()`）才写当日 bar，否则跳过当日留给盘后同步。
- [ ] **D2. success 判定改比例制**：全量/增量同步完成条件从 `completed > 0` 改为 `failed_symbols == 0`（或 filled 比例 ≥ 阈值如 95%）；未达标不写 `last_success_trade_date`，次日自动补缺自愈。
- [ ] **D3. NaN→0 过滤**：`_concurrent_fetch` 的 hist 归一化后过滤 `close<=0 or high<=0 or open<=0` 行，与 market_daily 路径对齐。
- [ ] **D4. 复权打标**：spot 补缺行在写入时标记 `adjust="raw"`（schema 加列或独立表），读取路径按请求 adjust 过滤；短期最小改动：spot 只补"当日缺失"，历史缺口一律走 qfq 源。
- [ ] **D5. 节假日过滤**：`enqueue_incremental_range` 入队前先过 `_resolve_trade_dates` 日历，节假日不入队。

### 第四批：事件循环与生命周期

- [ ] **P1. Torch 训练下线程**：`routers/first_limit_alpha.py` 5 个 async 路由全部包 `await asyncio.to_thread(...)`（对齐 backtest_lab 写法）。
- [ ] **P2. WS 广播背压**：`realtime.py` broadcast 改为遍历 `list(self._clients)` 快照；每次发送包 `asyncio.wait_for(timeout=5)`，超时/异常即 discard 并关闭。
- [ ] **P3. 大 SQL 下线程**：`build_snapshot_for_screen`、`get_existing_pairs` 大结果集调用、批量 `record_sync_batch` 包 `asyncio.to_thread`；SQL 用窗口函数只取每 symbol 最新两日。
- [ ] **P4. shutdown 顺序修正**：lifespan 先 cancel 并 await 全部任务（含 fire-and-forget 任务，用全局 set 收集引用 + done callback discard，总超时 20s），再执行 `_checkpoint_all_sqlite`。
- [ ] **P5. stop.sh 兜底误杀**：pgrep 结果追加端口/cwd 校验后再 kill。

### 暂缓（记录不在本轮）

- hermes_memory 同步 SQLite 下线程、full_diagnosis 超时预算、TradingAgents 线程取消、Tushare 限流器、notice funnel 读路径清空、前端轮询在途保护等中等问题 → 第二轮迭代。

## 验收标准

1. `pytest tests/` 全绿；CI 通过。
2. 手动验证：buy/focus 池放入至少 1 只股票 → 触发监控 tick → 返回包含 `kronos_predictions` 字段，无 TypeError。
3. 配置本地 Ollama 场景下触发 `/api/jobs/notice-screen`：请求发往 `OPENAI_BASE_URL` 而非 api.openai.com；断网时 LLM 打分降级为 disabled 且有日志。
4. 盘中（9:30–15:00）触发增量同步 → 当日 bar 不被 spot 数据覆盖。
5. LAN 内另一台设备 curl POST 任一写接口 → 403；浏览器打开公告 Tab → 无未转义 HTML。
6. 点击 first-limit-alpha 训练按钮期间，其它 API 请求响应正常（<1s）。
7. WS 打开两个客户端，广播期间反复连接/断开无 `RuntimeError: Set changed size during iteration` 日志。

## 风险与回滚

- S2 加鉴权可能影响现有 MCP 工具链路：MCP server 内部 fetch 同样带 `X-Alpha-Token` 头（从同一 env 读取），需同步修改。
- D4 若采用加列方案涉及 schema migration，SQLite 需 ALTER TABLE 兼容旧库（PRAGMA table_info 判断后迁移）；回滚 = git revert 单 commit。
- 分批提交：F1/F2、S1-S5、D1-D5、P1-P5 各一个 commit，出问题单独 revert。

## 关键决策记录

1. F1 选择依赖注入而非在 runtime 里重建 store/provider——避免双份 SQLite 连接和重复模型加载。
2. S2 选择"token + 回环白名单"而非完整用户体系——个人部署场景够用，复杂度最低。
3. D4 短期先做"spot 只补当日缺失"的最小方案，复权分表留到第二轮——控制单次变更风险。
