# Docker 支持 + 一键初始化（新手引导）

> 上游讨论：2026-08-24 会话「功能优化让它更适合别人用」。本文件只增不删。

## 背景 / 目标

新用户 fork 后的两大流失点：依赖栈重（torch/akshare/pandas）安装困难；首跑时数据库为空、各 Tab 空白无引导、Kronos 模型静默下载。目标：

1. 提供 `Dockerfile` + `docker-compose.yml`，`docker compose up -d` 一键起服务。
2. 数据库为空时提供"一键初始化"入口（数据中心欢迎卡 + 漏斗/预测页空状态引导）。
3. 预测页增加 Kronos 模型加载状态徽标。
4. 修正 `.env.example` 自相矛盾项；README 补 Docker 部署与零配置体验矩阵。

## 任务分解（checklist）

### A. Docker

- [ ] `Dockerfile`：`python:3.12-slim` 基础镜像；先装 CPU 版 torch（`--index-url https://download.pytorch.org/whl/cpu`，服务默认 CPU 推理），再装 requirements-base + kronos + mcp；不装 lightgbm 训练后端（可选功能）；WORKDIR=/app 对齐相对路径 `data/*.db`。
- [ ] `.dockerignore`：排除 .git/.venv/data/logs/tests/docs/.cursor/.pytest_cache 等。
- [ ] `docker-compose.yml`：端口默认映射 `127.0.0.1:18888:18888`（安全默认，注释说明如何开放 LAN）；`env_file: .env`；volume 挂载 `./data`、`./logs`；healthcheck 用 python urllib GET `/`；restart: unless-stopped。
- [ ] 验证 `docker compose config` 通过；尽量完成一次完整 build 冒烟。

### B. 一键初始化

- [ ] 后端：`POST /api/jobs/kline-cache/initialize`（routers/kline.py）——读取 `get_stats()` 判断 row_count，入队 full 同步任务（trigger_mode="initialize"，window_days 默认 120、夹取 30~365），返回 already_initialized 标志。
- [ ] 前端·数据中心：`index.html` 新增欢迎卡（row_count==0 时显示）：说明文案 + "一键初始化数据"按钮；提交后复用现有 dcProgressSection 进度条与 3s 轮询；running 中禁用按钮。
- [ ] 前端·漏斗/预测空状态引导：boot 时一次性拉取 stats 缓存；renderFunnel 与 loadPredictFunnel 在池全空且 DB 为空时注入"数据未初始化 → 去数据中心初始化"横幅（点击 switchTab('data')）。
- [ ] Kronos 状态：`KronosPredictService.status()` 公开方法 + `GET /api/predict/kronos/status`；预测工具栏加徽标（未加载/加载中/已就绪 三态），随预测 Tab 加载刷新。

### C. 配置与文档

- [ ] `.env.example`：ENABLE_TUSHARE 改 false 默认并改写注释；HOST 示例改 127.0.0.1 并注明 Docker 内部不受影响；补 ALPHA 场景说明行。
- [ ] README：Quick Start 增加 Docker 方式；项目结构树补 3 个新文件；API 列表补 2 个新端点；新增"零配置体验矩阵"表。

## 验收标准

1. `pytest tests/` 全绿；`./restart.sh` 流程按 AGENTS.md 步骤执行且服务健康。
2. 空库状态下打开数据中心 → 欢迎卡出现；点击初始化 → 进度条开始走；row_count>0 后欢迎卡消失。
3. 空库状态下策略选股/预测选股 Tab 出现初始化引导横幅；点击跳转数据中心。
4. `/api/predict/kronos/status` 返回 loaded/loading；预测页徽标三态正确。
5. `docker compose config` 校验通过；（若网络允许）镜像构建成功并能 curl 到 `/`。
6. 全部改动 commit 并 push 至 origin/main。

## 风险与回滚

- Docker build 下载 torch 较大（CPU 版约 200MB），CI 不引入 docker 构建，不影响现有流水线。
- 新端点均为只读/入队类操作，无 schema 变更；回滚 = revert 对应 commit。
- 前端仅增量渲染分支，不动既有卡片逻辑。

## 关键决策记录

1. 容器内 CMD 绑 0.0.0.0 属容器标准做法，宿主机暴露面由 compose 端口映射控制（默认仅回环）——与裸机 HOST 安全问题区分对待。
2. torch 用 CPU 轮子：kronos_predict_service 默认 device="cpu"，避免 CUDA 镜像 7GB+ 体积。
3. 初始化端点复用既有 enqueue_sync_trade_date(full) 队列机制，不新建同步路径，进度/日志/状态天然兼容。
4. DB 状态判断放前端一次性缓存 fetch，避免给每个空状态渲染加请求。
