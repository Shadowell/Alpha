# 背景 / 目标

GitHub issue #36「[P3][模型] 序列与多模态模型的增量验证」：FirstLimit Alpha 已有 GRU 训练入口，
但从来没有严格回答"序列 / 多模态模型是否真的比表格 baseline 更好"。打板样本少、噪声大，
复杂模型极易过拟合，若无统一 baseline + 统一口径的样本外对比，很容易陷入"模型越复杂越好"。

本计划的目标不是上线新模型，而是交付一套**可复用的增量验证脚手架**：
统一样本 / 统一时间切分 / 统一标签 / 统一回测口径，walk-forward + embargo 防泄漏，
样本外指标 + 成本后收益 + 硬判定门槛，并在不达标时明确输出"不保留"。

约束：本分支只新建文件（`strategy/model_validation/` + `tests/test_model_validation_*.py`），
不改动 `app/*`、`strategy/first_limit_alpha/*`、`requirements*.txt`、CI、deploy、根 README（由并行
agent 与主 agent 负责）。纯 numpy+pandas，CPU only，CI Python 3.11，重依赖只能 optional import。

# 目标产物

- 新包 `strategy/model_validation/`：contracts / splitting / metrics / portfolio / models / gate /
  runner / report / fixtures / cli + 包内 README（含主 agent 集成说明）。
- 新测试 `tests/test_model_validation_{splitting,metrics,portfolio,models,gate,runner,cli}.py`。
- 报告输出目录 `data/model_validation/`（`data/` 已 gitignore，不提交产物）。

# 验收标准（对应 issue 复选框）

1. 统一 baseline vs 序列 vs 融合对比报告，**至少 3 个滚动窗口**（`min_windows` 硬约束）。
2. 复杂模型不能稳定优于 baseline 时，明确记录"不保留"并落盘（`decision.json` blockers）。
3. 所有指标与回测口径一致：baseline 与候选走同一个 `evaluate_scores()` + `run_portfolio()`。
4. 推理延迟 / 训练成本 / 参数量 / 内存占用有报告，并纳入预算判定。
5. 模型卡完整：适用场景、失效场景、数据依赖、容量、成本、决策。
6. 单测覆盖：数据切分（含 embargo/purge/泄漏拒绝）、序列长度（error/truncate/pad）、
   缺失值（NaN/Inf 插补 + NaN 标签 + 特征数不匹配）、模型加载失败（缺依赖 / 损坏 artifact /
   未知类 / baseline 不可用）。

# 风险与回滚

- 风险：合成数据上的 keep/reject 只证明机制可用，不代表真实因子有效性。
  缓解：契约与列名可配置，真实数据接入后需重跑并重新校准 `GateConfig` 阈值。
- 风险：上游 #23/#26 的可成交口径与本文假定的 `can_buy/can_sell` 不一致。
  缓解：所有假设写在 `contracts.py` 顶部 INTEGRATION 段 + 包 README 第 5/7 节；缺失即 `reject`，
  不会误上线。
- 风险：CI 引入重依赖。缓解：只做 optional import + 单测里用 `sys.modules` 强制缺失路径。
- 回滚：本分支只新增文件，主 agent 不合并即可完全回退，对现有模块零影响。

# 关键决策记录

1. 新建独立包 `strategy/model_validation/` 而不是往 `strategy/first_limit_alpha/` 里加
   `sequence_eval.py` / `multimodal_eval.py`：issue 原文建议后者，但并行开发纪律把
   `strategy/first_limit_alpha/*` 判给 #23/#26/#27 agent，冲突代价更高；独立包 + 本地契约
   是可并行的最小方案，函数职责与 issue 的两个文件名一一对应
   （序列 = `SequenceTemporalModel` + runner 的 sequence 分支，多模态 = `ModelInput` 同时携带
   表格 + 序列 + 未来嵌入通道的融合入口 `RankBlendModel`）。
2. 内置模型用闭式 numpy 解，而非 sklearn/LightGBM：保证 CI 无 GPU、无新依赖、逐字节可复现，
   真实 LightGBM / GRU 通过 `ModelSpec` + 适配器接入。
3. "可成交性缺失 ⇒ 强制 reject"而不是"缺失就当作可成交继续算"：避免用乐观假设产出漂亮指标。
4. 判定采用"平均增量 + 胜出窗口占比"双条件：单个爆款窗口不能通过，符合 issue 对
   "≥3 个滚动窗口稳定优于 baseline"的要求。
