> 承接 [20261022-01_打板短线Alpha功能挖掘与Issue创建.plan.md](./20261022-01_%E6%89%93%E6%9D%BF%E7%9F%AD%E7%BA%BFAlpha%E5%8A%9F%E8%83%BD%E6%8C%96%E6%8E%98%E4%B8%8EIssue%E5%88%9B%E5%BB%BA.plan.md)。

## 背景 / 目标

- 15 个 open issue 构成打板 Alpha 的最小可信闭环，按依赖分为：数据底座 → 可执行标签 → 微观/情绪因子 → 可成交性回测 → 分层模型 → P2 增强 → P3 扩展。
- 目标：逐批在隔离 worktree 实现、测试、合并 main 并部署验证；每条 issue 必须有真实数据/API/测试证据，不以占位代码关闭。
- Tushare 权限先探测后开发；权限缺失走 issue 中明确降级，不得静默。

## 验收标准

- 每条 issue 有可运行实现、单元/集成测试、CI 通过、main 部署与线上 API 冒烟。
- 数据底座：能力矩阵可见、失败隔离、单位统一、覆盖率可查询。
- 标签：两种入场场景、多 horizon、晋级/炸板/断板/大面/可成交性均有测试。
- 因子：缺失值不填 0；as_of_time；无未来函数。
- 回测：一字板/涨停排队/跌停/停牌可成交性、容量、手续费、滑点；strict 默认。
- 模型：按板型分层，walk-forward + embargo，样本外增量报告。

## 风险与回滚

- 权限不足：能力矩阵标记 degraded，保留自算路径，不把空数据当成功。
- 数据库迁移：每表版本化，失败回滚迁移事务；线上验证只读，不手改卷内 DB。
- 大文件并行：严格模块所有权，跨 router/container 改动由主 agent 串行合并。
- 研究指标不显著：记录样本外基线和失败原因后关闭，不强行上线。

## 关键决策

1. #22 先完成，再并行标签/因子/回测。
2. 生产默认 strict 可成交性；宽松口径仅实验对比。
3. 打板数据复用 `market_kline.db`，避免增加运维库文件。
4. 所有模型/因子先离线验证，再进入策略 API，不直接接交易执行。
