# 接入 Tushare 可信数据源与修复数据链路

## 背景 / 目标

Alpha 当前同时使用 AKShare、东方财富、Sina 与本地 SQLite，但没有统一记录实际数据源及降级原因；交易日解析还可能把错误日期写入缓存。本计划对应 [GitHub Issue #1](https://github.com/Shadowell/Alpha/issues/1)，目标是建立可审计的 Tushare 主源数据链路，同时保留无 Token 时的安全降级能力。

## 任务分解（checklist）

- [ ] 增加仅从环境变量读取凭据的 Tushare Pro 客户端。
- [ ] 规范股票列表、交易日历与日线行情的数据格式和单位。
- [ ] 以 Tushare 为主源，东方财富 / AKShare 为显式降级源，并保留来源元数据。
- [ ] 修复 Sina 交易日解析器错误注入 `1992-05-04` 的问题。
- [ ] 增加单元测试、数据质量保护与无 Token 降级测试。
- [ ] 修复 GitHub Actions 中 API 回归测试未启动服务的问题。
- [ ] 更新 README 中的数据源、配置、格式和维护说明。
- [ ] 完成服务重启、测试、提交、PR、CI 检查与合并。

## 验收标准

- 仓库与 Git 历史中不包含 Tushare Token 或其他密钥。
- 配置 Token 时，股票主数据、交易日历和日线优先使用 Tushare。
- 未配置 Token 或 Tushare 请求失败时，系统可降级且能说明实际来源与原因。
- 日线数据继续符合 Alpha 的 SQLite K 线字段契约，成交额单位统一为人民币元。
- 交易日解析不再生成合成日期，相关回归测试通过。
- GitHub Actions 的 Python Tests 全部通过。
- PR 通过 `Closes #1` 自动关闭 Issue，并保留完整维护记录。

## 风险与回滚

- Tushare 权限和频率限制可能因账号等级不同而变化；通过可选配置、有限调用和显式降级控制风险。
- 本轮不直接删除历史 SQLite 数据；污染数据清理须先备份，再执行独立维护操作。
- 若新主源异常，可关闭 `ENABLE_TUSHARE` 恢复现有数据路径。

## 关键决策记录

- 复用 StockPro 已验证的“主源优先、整批降级、来源可追溯”原则，不复制其密钥或项目耦合代码。
- 实时行情继续使用现有东方财富链路；Tushare 第一阶段负责更稳定的股票主数据、交易日历与日线数据。
- 公开维护活动必须对应真实工程工作，不制造虚假 Issue、PR 或使用量。
